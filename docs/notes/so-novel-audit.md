# so-novel 代码审计与能力对照

> 审计对象：[`freeok/so-novel`](https://github.com/freeok/so-novel) v1.12.0（commit `88acec6`）
> 审计日期：2026-11-01
> 审计范围：86 个 Java 文件 / 6,401 行，含 core、parser、dsl、handler、utils、web、actions、launcher、bundle/rules
>
> **许可提示**：so-novel 采用 AGPL-3.0。本文只记录设计思想与实现取舍，**不包含**任何可复制的源码片段。本项目对这些能力的实现均为独立编写。

---

## 1. 定位

so-novel 是一套 **声明式规则引擎 + 单进程虚拟线程抓取 + 多格式合并器**。

它的重心全部押在"规则表达力"：新增书源只写 JSON，不改 Java。代价是调度、反爬基础设施、正确性保障都很薄。

本项目（novel-downloader）是 **CLI / REST API / 桌面 / 安卓四端同契约**，规则表达力原本不如它，但工程严谨度、测试覆盖、多端一致性远胜。

本文的目的是：**取其表达力，弃其工程债**。

---

## 2. 主流程

```
Main
 ├ 读 config.ini
 ├ 预热一次 V8（规避 SIGSEGV）
 ├ 建全局 OkHttp
 ├ 上报设备指纹（见 §7，安全问题）
 ├ auto-update=1 则同步检查更新（阻塞启动）
 └ -Dmode: tui | cli | web

搜索 → 选书 → 目录 → 逐章抓取（每章一个文件）→ 后处理合并 → 删临时目录
```

### 2.1 值得注意的设计：章节文件作为中间产物

目录展开成章节列表，每章独立落盘为 `0001_章节名.html`，最后由 post-handler 统一合并。

好处：TXT / EPUB / HTML / PDF 共用同一条抓取管线，合并器只负责拼装；文件名数字补零让字符串排序等于章节序；临时目录天然为断点续传留出改造点。

**本项目对照**：我们已经用 `ChapterStorage`（SQLite）做中间产物，比"每章一个文件"更强（事务、去重、脏标记、增量）。这条不需要抄，但"导出前对账"的思想要吸收——见 §6.1。

## 3. 并发模型

| 环节 | 机制 | 上限 |
|---|---|---|
| 章节下载 | 虚拟线程 + Semaphore + Phaser | min(50, 章节数)，硬顶 100 |
| 目录分页 | 虚拟线程 + Semaphore | 固定 5（硬编码） |
| 聚合搜索 | 每源一虚拟线程 + CountDownLatch | 书源数，**无上限** |
| 搜索分页 | `parallelStream()` | 公共 ForkJoinPool，**无上限** |
| 封面探测 | 3 虚拟线程 `invokeAll` | 3 |

**核心缺陷**：所谓"限流"是**每个线程自己 sleep**，不是全局令牌桶。50 并发 × 200–400 ms ≈ 160 req/s 打到源站。规则里的 `minInterval/maxInterval` 是每线程抖动，不是全局限速。

**本项目对照**：我们已有 `TokenBucketRateLimiter`（全局速率 + 突发容量 + 抖动），这是正确的抽象。不抄它的模型。

**可吸收的点**：并发抓取分页时，把结果按 `page_index` 存入映射再按序拼装，保证并发下顺序稳定。

## 4. 规则 DSL

### 4.1 格式

```
selector@js:抽取解密串;@java:base64.decode()
```

三段式执行：

1. **选区** —— 第一个 `@` 之前；`/`、`//`、`(` 开头走 XPath，否则 CSS
2. **取值** —— 含 `@href`/`@src` 取属性（`absUrl`），`meta[` 开头取 content，否则取 text/html
3. **后处理** —— 其余 `@lang:code` 依次执行，约定"入参是上一步结果，返回新结果"

执行器只有两个：`js`（Javet V8 池，代码包成 `function func(r){code; return r;}`）和 `java`（硬编码 `base64.decode` 与 `string.replace` 两个 case）。

### 4.2 三个聪明钩子

1. **`toc.list` 是 HTML 重写钩子** —— 抽出容器 `html()` 交给 JS 做字符串级改写，再重新 parse 跑 `item`。专治 CSS 隐藏的假章节、`onclick` 生成的链接、相对链接。
2. **`search.result` 可带 `@js:`** —— 先把整个响应体转成 HTML 再选，兼容 JSON 接口站。
3. **`nextChapterLink` 正则 + `END` 哨兵** —— 判断"已翻到下一章"，防止章内分页翻飞。

### 4.3 缺陷（审计确认）

| 缺陷 | 后果 |
|---|---|
| `@` 语义三重载：属性前缀 / DSL 分隔 / XPath 属性谓词 | `//div[@class='x']` 被截成 `//div[`，XPath 解析失败 |
| `toc.nextPage` 一字段两义（分页选择器 + 章节链接后处理） | 语义脆弱，当前仅因无人这么写而未爆雷 |
| 规则无 schema 校验 | 缺 `filterTxt` 在 `replaceAll(null)` 处 NPE，被重试吞掉后表现为"整本失败但原因不明" |
| 未知字段静默丢弃 | 规则里真实存在 `"ignoreSsl": true`，引擎无此字段，被静默忽略 |
| 文档单位错误 | 模板注释写"秒"，代码全按毫秒 |

**本项目决策**：不采用 `selector@js:...` 字符串 DSL。改用**显式 JSON 数组**（`steps`、`fallback`、`preprocess`），从根本上消除 `@` 冲突，并保持 `parse_rule` 的未知键拒绝策略。理由已写入 `plugins/rule/model.py` 的模块文档。

## 5. 正文清洗

顺序严格，简繁转换必须最后（这样模板里的标题也会被转换）：

```
抓取 HTML → ChapterFilter(删) → ChapterFormatter(段落归一) → ChapterRenderer(输出) → 简繁转换
```

- **Filter**：不可见字符（`\p{C}\p{Cf}\p{Co}\p{Zl}\p{Zp}\u200B\uFEFF`，针对盗版站 PUA 水印）、广告正则、广告标签、去重复标题、章节名规范化
- **Formatter**：`paragraphTagClosed=true` 时把非 `<p>` 成对标签全改写成 `<p>`；`false` 时按 `<br>+` split 再包 `<p>`
- **Renderer**：TXT 用 `<p>` 正则抽段加两个全角空格；EPUB/HTML/PDF 走 FreeMarker 模板

### 5.1 两个真实污染 bug（反面教材）

1. `HtmlUtils.clearAllAttributes` 调用 `StrUtil.cleanBlank`，**删除所有空白**——中英混排的单词间空格粘连。而 `ChapterFormatter` 的注释专门写着"content 不应被 cleanBlank"，前后矛盾。
2. HTML 实体正则 `&[^;]+;` 全删，把 `&amp;amp;`、`&amp;lt;` 也删了，正文里本该显示的 `&`、`<` 消失。

**本项目决策**：只吸收"清洗项清单"，不吸收"用破坏性正则解决格式问题"的做法。凡是可能误删正常内容的清洗项默认关闭，并在测试中锁定"正常文本不受影响"。

## 6. 正确性：最严重的短板

### 6.1 静默缺章

```
章节重试耗尽 → 返回 null → createChapterFile 直接 return
                ↓
        进度计数照常 incrementAndGet()
                ↓
        最后无条件打印"完成"
```

用户拿到缺章的书，看到的是成功提示。目录分页失败也只打一行日志跳过整页。合并前没有章节数对账。`TocList` 还按标题去重——分卷里的同名章节（"第一章"）会被真的删掉一章。

**本项目决策（最高优先级）**：补"缺章账本 + 合并前对账"。进度 100% 必须等价于章节完整，否则明确告警或按 `--strict` 失败。

### 6.2 其他

| 问题 | 后果 |
|---|---|
| `enable-retry=0` 时在工作线程直接 `System.exit(1)` | Web 模式下连服务一起杀 |
| 全链路不检查 HTTP 状态码 | 403/429/502 页面被当正文解析 |
| 章内分页 / 目录下一页递归无最大页数、无循环检测 | 源站自指链接导致无限循环 |
| 无断点续传，章节文件覆盖写，完成后删缓存 | 中途崩溃全量重下 |
| 虚拟线程任务从不 `Future.get()` | 任务异常被静默吞掉 |

## 7. ⚠️ 安全问题

### 7.1 设备指纹上报

`Main.java:68` 每次启动**无条件**调用 `ClientReportRepository.report()`，收集并 POST：

```
用户名、主机名、MAC 地址、内网 IP、OS 名称/架构/版本、应用版本
```

目标地址是 Base64 混淆的硬编码 Workers 域名（审计时已解码确认，此处不复述）。类注释写着"仅限代理用户"，但**调用点没有任何条件判断**。失败重试 3 次，无告知、无开关、无提示。

这是本次审计中性质最严重的问题。

### 7.2 Web 层

- 全部 GET、**无任何鉴权**
- `/config` 直接吐出 `qidianCookie`
- `RespUtils` 把所有异常统一转成 HTTP 500
- 前端 Alpine.js + Tailwind 全走 CDN，离线不可用

### 7.3 自动更新

启动时同步阻塞执行 → 取 `/releases` 数组第 0 个（不排除 prerelease）→ **直接下载 tar.gz 到上级目录**，无 checksum、无签名、不解压、不安装，目标路径还可能不可写。

**本项目决策**：保持"只提示、不自动安装"的安全立场；补资产解析、镜像回退、SHA256 校验，但下载后的执行/替换必须由用户完成。

## 8. 能力对照与取舍

| so-novel 能力 | 本项目原状 | 决策 |
|---|---|---|
| 规则 DSL 后处理链 | `Field` 只有 selector/regex/replace | **采纳**，改为显式 `steps` 数组 |
| 字段选择器回退链 | 无 | **采纳** `Field.fallback` |
| `toc.list` HTML 重写钩子 | 无 | **采纳**，做成 section 级 `preprocess` |
| 声明式分页停止条件 | 只有 `max_pages` | **采纳** `stop_when` + `loop_guard` |
| 规则级并发/间隔/重试 | 全局配置 | **采纳**，但用不可变合并 |
| 查询意图判定（书名 vs 作者） | `max(title, author*0.9)` | **采纳** |
| 书源 HEAD 健康探测 | 只验证能否实例化 | **采纳** |
| 缺章账本 + 合并对账 | 无 | **采纳**（最高优先级） |
| 批量"书名 作者" + 未找到回传 | 无 | **采纳** |
| PUA 水印 / 重复标题 / 章节名规范化 | 部分 | **采纳** |
| 编码自动判定 | 已有 BOM+header+回退链 | **不采纳**（我们已更强） |
| 每线程 sleep 限流 | 全局令牌桶 | **不采纳**（我们已更强） |
| 章节文件作为中间产物 | SQLite 章节存储 | **不采纳**（我们已更强） |
| 共享可变全局配置 | 已有配置副本 | **明确禁止** |
| `@` 语义重载 | 严格 schema 校验 | **明确禁止** |
| 失败静默降级 | — | **明确禁止** |
| 工作线程 `System.exit` | — | **明确禁止** |
| Web 无鉴权 / CDN 依赖 | Token 鉴权 / 本地资源 | **明确禁止** |
| 设备指纹上报 | — | **明确禁止** |

## 9. 结论

so-novel 是"**规则表达力换工程严谨度**"的典型样本：用 6,401 行做到 13 个书源零代码接入 + 四格式输出，规则 DSL 的表达力确实值得研究；但代价是静默缺章、零断言测试、无鉴权 Web，以及一个藏在 Base64 后面的设备指纹上报。

对本项目而言，吸收顺序应为：

1. **缺章账本 + 对账**（补正确性）
2. **规则 DSL 的 steps / fallback / preprocess / 分页守卫**（补表达力）
3. **查询意图判定**（提升搜索体验）
4. **书源健康探测、批量下载闭环、导出可靠性**（补体验）
5. **更新检查的资产解析与校验**（补分发完整性）

前两项是纯收益补强，风险最低；规则引擎改造需要重点回归，因为它是所有站点规则的地基。
